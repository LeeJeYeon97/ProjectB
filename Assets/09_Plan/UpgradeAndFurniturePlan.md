# 매장 성장 기능 구현 순서와 설계

## 목표

플레이어 능력치, 직원, 기계, 좌석을 단계적으로 강화해 손님을 더 효율적으로 응대하는 매장 운영 게임으로 확장한다. 좌석은 현재 씬에 고정 배치되어 있지만, 최종적으로는 플레이어가 가구 배치 모드에서 직접 놓을 수 있도록 설계한다.

## 프로젝트 현재 구조에서 확인한 점

- 플레이어 재화는 `PlayerController.money`에 있고, `UpdateMoney()`와 `SetMoney()`로 바뀐다. 현재 코드에는 구매에 쓸 재화 차감 함수가 없다.
- `Stat`은 기본값, 추가값, 배율을 계산하는 공용 클래스지만, 현재 플레이어 이동과 직원 작업 속도는 각 컨트롤러의 필드로 관리된다.
- 직원 고용은 `EmployeeManager.HireEmployee()`에 구현되어 있고, 직원 이동 속도와 테이블 청소 시간은 `EmployeeController`가 직접 가진다.
- 좌석은 `SeatStation` 컴포넌트가 `Start()`에서 `StationManager`에 등록된다. `CustomerManager`는 등록된 좌석에서 빈 좌석을 찾는다.
- 구역 해금은 `UnlockManager`와 `UnlockAnchor` 흐름이 있지만, 해금 저장 함수는 현재 비어 있다. 자유 배치 가구의 저장은 별도 설계가 필요하다.
- 현재 기계 상호작용 대상에는 `BeerMachine`이 있다. 기계 업그레이드 값은 기계별 설정으로 적용하는 편이 적합하다.

## 권장 구현 순서

### 0. 공통 기반: 재화 지불, 업그레이드 데이터, 저장

각 기능을 따로 구현하기 전에 구매와 저장의 최소 규칙을 정한다.

1. `PlayerController`에 재화가 충분한지 확인하고 성공하면 차감하는 `TrySpendMoney(int amount)`를 추가한다. 재화가 부족하거나 금액이 0 이하일 때는 차감하지 않고 실패를 돌려준다.
2. 업그레이드 항목별로 고유 ID, 표시 이름, 최대 단계, 단계별 가격, 단계별 효과를 저장한다. 고정 밸런스는 ScriptableObject 데이터로 두고, 보유 단계는 플레이어 저장 데이터로 분리한다.
3. 업그레이드 구매는 한 흐름으로 처리한다: 구매 가능 여부 확인 → 재화 차감 → 단계 기록 → 대상 능력치에 적용 → UI 갱신 → 저장.
4. 런타임 매니저나 씬 오브젝트가 파괴되어도 구매 단계와 가구 배치 정보가 유지되도록 저장 경로를 먼저 선택한다. 현재 `UnlockManager`의 저장 코드는 미완성이므로 기존 코드가 이미 저장을 보장한다고 가정하지 않는다.

초기에는 범용 업그레이드 프레임워크를 지나치게 크게 만들지 않는다. 공통 구매 흐름과 데이터 형식은 공유하고, 실제 효과 적용은 플레이어·직원·기계 각 컴포넌트가 담당한다.

### 1. 플레이어 능력치 업그레이드

**첫 구현 대상으로 권장한다.** 플레이어 한 명에게 적용하므로 구매와 효과 연결을 빠르게 확인할 수 있다.

- 우선 후보: 이동 속도, 상호작용 시간 감소, 한 번에 들 수 있는 아이템 수.
- 현재 이동 속도 값을 실제로 적용하는 위치를 먼저 확인하고, 업그레이드 값을 그곳에 연결한다. `Stat`을 사용한다면 기본값과 업그레이드 추가값을 합산한 결과를 이동 시스템에 전달한다.
- 상호작용 시간은 `InteractableBase`와 각 상호작용 대상의 `Duration` 계산에 영향을 주므로, 플레이어 보너스가 어떤 상호작용에 적용되는지 범위를 명확히 한다.
- 적재량 업그레이드는 `StackingSystem`의 최대 적재 수 제한과 연결한다. 최대 수 제한이 아직 한 곳에서 관리되지 않는다면 먼저 기준값과 검사 위치를 한 곳으로 모은다.
- 구매 UI에는 현재 단계, 다음 단계 효과, 가격, 재화 부족 상태를 표시한다.

**완료 기준:** 재화를 지불해 단계가 오르고, 씬을 다시 열어도 단계가 유지되며, 실제 플레이에서 선택한 능력치 변화가 체감된다.

### 2. 직원 업그레이드

직원 고용은 이미 구현되어 있으므로, 기존 고용 흐름과 별도로 **고용한 직원의 능력치를 향상시키는 흐름**을 추가한다.

- 첫 버전은 청소 직원의 작업 시간 감소 또는 이동 속도 증가처럼 `EmployeeController`의 현재 작업에 직접 연결되는 효과로 제한한다.
- 업그레이드 적용 범위를 먼저 정한다. 권장 기본안은 업그레이드 구매 시 고용된 모든 직원과 이후 고용되는 직원에게 같은 단계가 적용되는 방식이다. 직원별 개별 성장으로 바꾸려면 직원마다 저장 ID와 단계가 추가로 필요하다.
- 속도는 NavMeshAgent 초기화 시 고정값으로만 넣지 말고, 능력치 변경 후에도 다시 적용할 수 있는 함수로 분리한다.
- 작업 시간 감소는 `cleanDuration`을 직접 덮어쓰기보다 기준 시간과 업그레이드 효과에서 계산한다. 최소 작업 시간이 0이 되지 않도록 제한한다.
- 이후 직원 종류나 담당 업무별 업그레이드가 필요해지면 직원 종류 또는 업무 ID를 데이터에 추가한다.

**완료 기준:** 기존 고용 기능이 유지되고, 업그레이드 후 현재 직원과 신규 직원 모두 정책에 맞게 강화되며 저장 후에도 단계가 복원된다.

### 3. 기계 업그레이드

기계별 특성과 업그레이드 효과를 구분해, 다른 기계를 추가해도 기존 기계 코드를 크게 복사하지 않도록 한다.

- 첫 적용 대상은 `BeerMachine`으로 한다. 후보 효과는 음료 제작 시간 감소, 한 번에 생산 가능한 수량 증가, 기계 보관량 증가다.
- 기계 프리팹에는 고유 기계 ID 또는 데이터 참조를 두고, 업그레이드 단계는 해당 ID를 기준으로 저장한다. 기계가 여러 대일 때 전역 업그레이드인지 기계별 업그레이드인지 규칙을 분명히 한다. 첫 버전은 같은 종류의 모든 맥주 기계에 적용되는 전역 단계가 간단하다.
- 업그레이드 효과를 `BeerMachine`의 인스펙터 기본값과 합산한 뒤 제작 시작과 완료 판정에 사용한다.
- 장비의 작동 중 업그레이드가 가능한지 정책을 정한다. 초기 버전은 작동 중에는 구매를 막거나, 다음 제작부터 적용하는 편이 안전하다.
- 추후 다른 기계를 추가할 때 공통 구매 로직은 재사용하고, 기계 고유 효과만 각 기계가 제공한다.

**완료 기준:** 맥주 기계 업그레이드가 실제 제작 흐름에 반영되고, 가격·단계·효과가 저장되며 재접속 뒤에도 복구된다.

### 4. 가구 배치 기반을 만들고 좌석 늘리기

좌석은 장기적으로 플레이어가 놓는 가구가 되므로, **고정 좌석 수를 별도 숫자로 늘리는 기능은 만들지 않는다.** 배치된 `SeatStation`의 수가 실제 좌석 수가 되게 한다.

#### 4-1. 현재 좌석 등록 구조 정리

- `StationManager`를 씬에 이미 놓인 좌석과 나중에 동적으로 놓는 좌석 모두를 관리하는 등록부로 사용한다.
- 좌석이 활성화될 때 등록하고, 비활성화되거나 제거될 때 등록 해제한다. 현재 `Start()` 등록만으로는 런타임 설치·철거 생명주기를 다루기 어렵다.
- 중복 등록을 막고, 손님이 찾을 때 비활성·철거 중인 좌석은 제외한다.
- 고정 배치된 기존 좌석도 같은 등록 경로에 들어가도록 해, 가구 배치 도입 전후에 손님 배정 코드를 갈아엎지 않게 한다.

#### 4-2. 최소 배치 모드

한 번에 복잡한 건축 시스템을 만들지 말고 의자 하나의 배치 흐름부터 만든다.

1. 가구 목록에서 의자를 선택한다.
2. 마우스 또는 모바일 입력 위치에 미리보기 의자를 표시한다.
3. 회전 입력으로 방향을 바꾼다.
4. 바닥/구역 안인지, 다른 가구와 겹치지 않는지 검사하고 가능·불가 상태를 색이나 표시로 알려준다.
5. 확정하면 비용을 지불하고 실제 의자 프리팹을 생성한다. 취소하면 미리보기만 제거하고 비용은 쓰지 않는다.
6. 배치 위치, 회전, 가구 ID를 저장하고 씬 진입 때 복원한다.

가구 배치 데이터에는 `가구 ID`, `위치`, `회전`, 필요하면 `해금 상태`를 넣는다. 프리팹 참조 자체를 저장하지 말고 ID를 이용해 데이터베이스에서 프리팹을 찾는다.

#### 4-3. 좌석 구매와 확장

- 의자 구매가 성공해 실제 `SeatStation` 프리팹이 배치되면 `StationManager`에 등록되도록 한다.
- 좌석 수 UI는 고정된 증가 횟수가 아니라 현재 사용할 수 있는 등록 좌석 수를 표시한다.
- 플레이어가 의자를 옮기거나 철거할 수 있게 할 때는 손님이 사용 중이거나 예약된 좌석은 이동·철거할 수 없게 한다.
- 테이블과 의자가 별도라면, 첫 버전은 좌석 하나만으로 동작시키거나 의자와 테이블을 하나의 가구 묶음으로 배치한다. 여러 좌석이 테이블 하나를 공유하는 구조는 후속 작업으로 미룬다.

**완료 기준:** 기존 고정 좌석과 플레이어가 놓은 의자가 모두 같은 손님 배정 목록에 들어가고, 배치한 좌석의 저장·복원 및 유효하지 않은 위치 제한이 동작한다.

## 공통 UI와 데이터 흐름

```text
업그레이드/가구 선택 UI
        ↓ 구매 요청
구매 가능 여부 및 재화 확인
        ↓ 성공
단계 또는 배치 데이터 갱신
        ↓
플레이어 / 직원 / 기계 / 좌석 시스템에 효과 적용
        ↓
UI 갱신 및 저장
```

UI는 가격과 현재 효과를 보여주고 구매 요청만 보낸다. 재화 확인, 단계 기록, 효과 적용, 저장은 게임 로직이 처리해 UI 코드가 게임 규칙을 직접 바꾸지 않도록 한다.

## 구현 규칙

- 코드의 클래스, 함수, 변수 이름은 짧고 알아보기 쉽게 작성한다.
- 새로 작성하거나 수정하는 함수와 중요한 처리에는 동작 이유와 흐름을 설명하는 한국어 주석을 자세히 단다.
- 업그레이드 가격과 효과 수치를 코드 곳곳에 중복해서 쓰지 않고 데이터 한 곳에서 관리한다.
- 이동 속도나 작업 시간이 바뀌면 실제 에이전트와 작업 판정 값에도 다시 적용되는지 확인한다.
- 구매 실패 시 재화나 단계가 일부만 바뀌지 않도록 구매 처리를 한 흐름에서 완료한다.
- 저장 형식에는 버전 또는 기본값 복구 방식을 고려해 추후 업그레이드 항목이 늘어도 기존 저장 데이터가 깨지지 않게 한다.

## 먼저 만들 작은 범위

첫 작업 묶음은 다음처럼 제한하는 것을 권장한다.

1. 재화 차감 성공/실패 함수 추가
2. 플레이어 이동 속도 업그레이드 3단계와 가격 데이터
3. 간단한 구매 UI 연결
4. 업그레이드 단계 저장 및 복원
5. 이 구조를 직원 청소 속도 업그레이드에 재사용

이 흐름이 안정된 다음 기계 업그레이드를 추가하고, 좌석 확장 시점에 좌석 등록 생명주기를 정리한 뒤 의자 배치 모드를 만든다.
