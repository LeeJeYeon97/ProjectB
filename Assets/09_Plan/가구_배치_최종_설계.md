# 가구 배치 최종 설계

## 설계 결정

가구 배치는 **자유 위치 배치에 90도 회전을 적용하는 혼합 방식**으로 구현한다.

- 가구 위치는 바닥에서 연속적인 월드 좌표로 정한다. 기본 격자에 강제로 맞추지 않는다.
- 방향은 모바일 조작과 손님 동선을 고려해 90도 단위로 회전한다.
- 방 또는 배치 가능 구역 안에 가구 전체가 들어오고, 다른 배치물과 겹치지 않을 때만 확정한다.
- 선택적 미세 스냅은 후속 편의 기능으로 둔다. 첫 버전의 필수 조작에는 넣지 않는다.

이 방식은 현재 프로젝트의 3D 바 운영과 맞는다. 의자와 영업 설비는 손님·직원·상호작용 시스템과 연결되므로, 위치를 자유롭게 정하면서도 방향과 배치 규칙은 단순하게 유지하는 편이 적절하다.

## 프로젝트에서 확인한 기반

- `Assets/01_Scripts/Content/FurniturePlacementController.cs`에 가구 미리보기, 바닥 레이캐스트, 겹침 검사, 회전·확정·취소 입력, 저장과 복원이 이미 있다.
- 현재 위치 계산은 `gridSize` 값으로 X/Z 좌표를 반올림하므로, 이 부분을 제거하면 자유 위치 이동의 기반이 된다.
- 컨트롤러는 마우스와 첫 번째 터치를 읽고, 회전·배치·취소 버튼을 만든다. 저장 데이터에는 가구 ID, 월드 위치, 회전값이 들어간다.
- `FurnitureCatalog`은 가구 ID, 표시 이름, 가격, 프리팹을 보관한다.
- 현재 가구 카탈로그와 화면 연결은 의자 배치 중심이다. 다양한 가구를 추가하기 전에 가구별 배치 규칙과 상호작용 연결을 데이터로 확장한다.
- 현재 터치 확정은 손가락을 뗄 때가 아니라 누른 순간에 발생한다. 드래그 조작과 버튼 입력이 충돌하지 않도록 입력 흐름을 정리해야 한다.

## 플레이어 조작

1. 가구 목록에서 설치할 가구를 선택한다.
2. 배치 모드로 전환하고, 선택한 가구의 반투명 미리보기를 표시한다.
3. 화면을 한 손가락으로 누르고 움직여 미리보기 위치를 조정한다.
4. 화면의 회전 버튼으로 가구를 90도씩 돌린다.
5. 배치 가능 상태와 불가 상태를 색상 또는 명확한 표시로 구분한다.
6. 별도의 **배치** 버튼을 눌러 확정하고, **취소** 버튼으로 배치 모드를 끝낸다.

배치 버튼을 별도로 두어 손가락을 놓는 동작만으로 구매가 확정되지 않게 한다. UI 위에서 시작된 터치는 바닥 이동으로 처리하지 않는다. 배치 모드에서는 플레이어 이동 입력을 막고, 카메라 제스처와 가구 이동 입력도 서로 분리한다. 첫 버전은 한 번에 한 손가락만 배치 조작에 사용한다.

## 배치 검사 규칙

### 바닥과 구역

- 카메라에서 터치 지점으로 광선을 쏘고, 지정된 바닥 레이어에 닿은 위치를 미리보기 위치로 사용한다.
- 배치 구역은 충돌체 또는 전용 영역 데이터로 명시한다. 바닥 아무 곳이나 설치 가능하게 두지 않는다.
- 가구의 배치 영역 전체가 허용 구역 안에 있어야 한다. 중심점만 구역 안에 있는 것으로는 확정하지 않는다.
- 벽, 문, 카운터 뒤 작업 공간 등 설치가 금지된 영역은 별도 차단 영역으로 표현한다.

### 겹침과 동선

- 외형 메시 전체를 검사 기준으로 삼기보다, 프리팹에 배치 검사 전용 콜라이더를 둔다. 콜라이더는 바닥에서 차지하는 공간을 단순하게 나타낸다.
- 다른 가구, 벽, 고정 설비와 겹치면 배치를 막는다. 바닥과 미리보기 자신의 콜라이더는 검사에서 제외한다.
- 플레이어·손님·직원은 순간적인 위치 겹침만으로 설치 불가 판정을 내리지 않는다. 대신 통로와 작업 공간을 차단하는 배치를 막는 규칙을 둔다.
- 의자는 기존 좌석 검사와 연결해 의자끼리 지나치게 가까운 배치를 막는다.
- 배치 검사는 미리보기와 확정 직전에 모두 수행한다. 확정 직전에도 유효한 경우에만 비용을 차감한다.

### 미리보기와 확정

- 미리보기는 좌석 등록, 상호작용, 손님 배정, 저장에 참여하지 않는다.
- 배치할 수 있으면 초록색 계열, 불가능하면 빨간색 계열로 보여주고, 색에만 의존하지 않도록 상태 문구나 아이콘도 제공한다.
- 확정 순서는 위치 재검사 → 재화 확인 및 차감 → 실제 프리팹 생성 → 기능 시스템 등록 → 배치 데이터 저장으로 한다.
- 취소 또는 재화 부족 시 미리보기만 정리하고 실제 가구와 저장 데이터는 변경하지 않는다.

## 코드와 데이터 역할

기존 구조를 활용하고, 역할이 커지는 경우에만 작은 컴포넌트로 나눈다.

- **가구 카탈로그**: 가구 ID, 이름, 가격, 프리팹과 배치 규칙을 제공한다.
- **배치 컨트롤러**: 가구 선택, 미리보기, 터치 입력, 회전, 확정, 취소를 관리한다.
- **배치 영역**: 허용 바닥과 금지 구역을 제공한다.
- **배치 검사**: 영역 포함, 콜라이더 겹침, 가구별 간격 규칙을 판정한다.
- **배치 표식**: 배치된 오브젝트의 가구 ID를 보관해 저장·복원과 편집에 사용한다.
- **기능 가구**: 의자 등 기존 상호작용 컴포넌트를 유지하고, 실제 설치된 뒤에만 관련 매니저에 등록한다.

가구 설정에는 다음 항목을 단계적으로 추가한다.

- 고유 ID, 표시 이름, 가격, 프리팹
- 배치 검사 모양 또는 배치 콜라이더 참조
- 허용 회전 방식(첫 버전은 90도 단위)
- 가구 종류별 규칙(예: 의자 최소 간격, 벽에 붙여야 하는 설비)

## 저장과 기능 연결

- 저장 단위는 가구 ID, 위치, 회전으로 유지한다. 프리팹 자체를 저장하지 않는다.
- 씬 진입 시 카탈로그에서 ID에 맞는 프리팹을 찾아 생성하고, 실제 기능 가구만 각 시스템에 등록한다.
- 저장 형식 버전을 유지하고, 알 수 없는 ID나 잘못된 저장 항목은 건너뛴다.
- 좌석은 실제 설치된 `SeatStation`만 좌석 관리 시스템에 등록한다. 생성 시 등록하고 비활성화·철거 시 등록 해제하는 생명주기로 정리한다.
- 손님이 사용 중이거나 예약한 좌석은 이동·철거할 수 없게 한다.
- 저장 방식은 현재의 `PlayerPrefs` JSON을 첫 구현에서 재사용한다. 배치 수와 저장 규모가 커지면 기존 게임 저장 체계로 옮긴다.

## 구현 순서

### 1단계: 현재 의자 배치 안정화

- 격자 반올림을 제거하고 자유 위치 미리보기를 만든다.
- 터치 위치 이동과 배치 확정 입력을 분리한다. 위치 조정은 터치 드래그, 확정은 화면 버튼으로 처리한다.
- 배치 모드에서 플레이어 조작을 막고 UI 터치가 바닥 입력으로 새지 않게 한다.
- 기존 회전, 취소, 비용 차감, 저장·복원을 유지한다.

### 2단계: 배치 규칙과 피드백 보강

- 방의 허용 구역과 금지 영역을 분리한다.
- 프리팹마다 배치 검사 전용 콜라이더를 지정한다.
- 전체 가구 영역 기준으로 방 경계와 겹침을 검사한다.
- 유효 여부를 미리보기 색과 UI 안내로 표시한다.

### 3단계: 좌석 시스템과 연결

- 동적으로 생성·복원되는 좌석도 기존 손님 좌석 목록에 등록되게 한다.
- 사용 중인 좌석의 이동·철거를 제한한다.
- 저장된 좌석이 복원된 뒤 좌석 목록에 중복 없이 등록되는지 확인한다.

### 4단계: 가구 종류 확대

- 카탈로그에 테이블, 장식, 영업 설비를 추가한다.
- 가구별 배치 조건과 기능 시스템 등록을 분리한다.
- 필요하면 이동·회수·철거와 미세 스냅을 추가한다.

## 완료 기준

- 모바일에서 한 손가락으로 미리보기를 옮기고, UI 버튼으로 회전·확정·취소할 수 있다.
- UI 터치가 가구 이동이나 배치 확정으로 오인되지 않는다.
- 방 밖, 금지 구역, 벽·가구와 겹치는 위치에는 설치되지 않는다.
- 배치 불가 상태가 사용자가 이해할 수 있게 표시된다.
- 재화가 부족하거나 설치가 취소되면 재화와 저장 내용이 바뀌지 않는다.
- 저장 후 재진입하면 위치·방향·가구 종류가 복원되고 기능 가구가 해당 시스템에 한 번만 등록된다.
- 기존 손님 이동, 좌석 사용, 직원 작업이 배치 기능 도입 후에도 동작한다.

## 첫 구현 범위

첫 작업에서는 **의자 하나의 모바일 자유 위치 배치**만 완성한다. 위치는 자유롭게 두고, 회전은 90도 단위로 제한하며, 배치 버튼으로 확정한다. 배치 구역·겹침 검사·재화 차감·좌석 등록·저장 복원까지 이 가구 하나로 확인한 뒤 같은 흐름을 다른 가구에 확장한다.
